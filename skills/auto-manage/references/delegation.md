# Brief a worker or reviewer

Where the host exposes model tier or effort, choose a fast low-cost tier for mechanical work, standard for ordinary implementation, and the strongest tier for Full-tier planning, security review or hard diagnosis. Otherwise use the configured default.

Give a worker one objective, owned files, exclusions, tier, checkable criteria, required receipts, stop gates and expected report fields. Use paths and line ranges. Workers save results to files and return status, changed paths, receipts and blockers.

Give an independent reviewer the contract, bounded diff, sanitized evidence and specific questions. If isolation is unavailable, record the actual review method and its limits. Verify each must-fix against source. Reuse a worker or reviewer only for the same repo and objective; send deltas.
